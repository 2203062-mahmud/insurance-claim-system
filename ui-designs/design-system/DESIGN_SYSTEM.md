## Brand & Style

This design system establishes an ultra-precise, high-integrity visual environment crafted for mission-critical enterprise insurance claim lifecycle automation, adjudication, and treasury surveillance.

### Brand Personality & Emotional Impact
The visual posture conveys unassailable security, clinical precision, and institutional solvency. It strips away mundane enterprise bureaucracy in favor of a sleek, high-conviction command deck. Users—ranging from tier-3 claim investigators and risk actuaries to claims executives—must experience deep focus, total operational control, and confidence in automated audit trails.

### Design Movement & Aesthetic Direction
The visual architecture pairs **Technical Minimalism** with **Deep-Surface Glassmorphism** and targeted **Bioluminescent Accents**. 
- **Substrate:** Deep obsidian and cold slate foundations eliminate optical fatigue during long operational cycles.
- **Atmosphere:** Controlled emerald and cyan light fields imply computational precision, liquidity, and verified state transitions.
- **Structural Integrity:** Frosted dark-field surfaces with razor-sharp specular borders create clear spatial hierarchy without resorting to heavy structural dividers or visual clutter.
- **Data Density:** High-density, balanced interfaces prioritize high-throughput claim auditing, telemetry verification, and policy disbursement without cognitive friction.

## Colors

The system uses a calibrated chromatic hierarchy calibrated specifically for dark-mode data density, financial reconciliation, and real-time claim status tracking.

### Primary Spectrum (Emerald Treasury)
The emerald continuum signifies approved states, positive reserves, operational liquidity, and algorithmic validation.
- **Base Emerald (`#10B981`):** Primary interactions, affirmative status badges, active indicators.
- **Deep Emerald (`#059669`):** Hover interactions, high-contrast borders, focus rings.
- **Luminous Emerald (`#34D399`):** Micro-glow anchors, key financial KPIs, pulse states for real-time claims.

### Secondary Spectrum (Cyan Telemetry)
The cyan continuum designates streaming events, external API telemetry, document validations, and active workflow states.
- **Electric Cyan (`#06B6D4`):** Active step indicators, secondary actions, chart accents.
- **Sky Cyan (`#38BDF8`):** Data linkages, hash tooltips, active tab indicators.

### Neutral Substrates (Obsidian & Cold Slate)
Surfaces are built from low-luminance, slate-tinted deep neutrals rather than dead carbon black to maintain visual depth and preserve specular highlights.
- **Void Obsidian (`#090D14`):** Canvas background, root workspace backing.
- **Deep Obsidian (`#0D131F`):** Structural sidebars, persistent master headers, container frames.
- **Elevated Obsidian (`#131D2E`):** Card panels, data table headers, modal surfaces.
- **Subtle Slate Surface (`#1E293B`):** Selected table rows, input fields, interactive chip defaults.

### Functional & Semantic Tokens
- **Border Subtle:** `rgba(255, 255, 255, 0.06)` for standard structural containment.
- **Border Emerald Accent:** `rgba(16, 185, 129, 0.20)` for verified nodes, focused cards, and primary triggers.
- **Border Cyan Accent:** `rgba(6, 182, 212, 0.25)` for active step states and processing signals.
- **Critical Failure / Fraud Alert:** `#F43F5E` (Crimson) for flagged claim fraud vectors.
- **Warning / Review Required:** `#F59E0B` (Amber) for adjuster adjudication queues.

## Typography

The typographic hierarchy is divided into three distinct roles:
1. **Structural Headers (`Plus Jakarta Sans`):** Delivers clean geometry with subtle warmth, preventing harsh coldness while maintaining executive presence.
2. **Dense Interface Prose (`Inter`):** Selected for high micro-legibility, neutral personality, and optimal tabular performance in dense operational dashboards.
3. **Monospaced Data Streams (`JetBrains Mono`):** Dedicated to all policy identifiers, claim transaction hashes, financial currencies, actuarial loss ratios, and timestamps.

### Usage Standards
- Display metrics (e.g., Claim Total Reserves `$14,820,400.00`) must strictly utilize `metric-display` with tabular numbers (`tnum`) enabled.
- All technical hashes, claim tracking UUIDs, and blockchain/audit attestations must use `code-sm` or `code-xs`.
- Section classification headers across inspectors and side panels utilize uppercase `label-caps` in secondary text tokens (`text-slate-400`).

## Layout & Spacing

The layout model is governed by an asymmetric **12-column adaptive fluid grid** engineered for data-intensive administrative consoles and multi-pane inspection workspaces.

### Grid Structure & Adaptation
- **Desktop (1440px+):** 12 columns, fixed 256px or 72px (icon-collapsed) global navigation rail, 380px contextual inspector pane (collapsible), 20px (`space-lg`) gutters, 32px (`space-xl`) canvas margins.
- **Laptop / Standard Workstation (1024px - 1439px):** 12 columns, 16px gutters, 24px margins. Contextual inspector shifts to an overlay sheet mode.
- **Tablet (768px - 1023px):** 8 columns, 16px gutters, 16px margins. Complex data grids switch to priority-column visibility with expandable row details.
- **Mobile (< 768px):** 4 columns, 12px gutters, 16px margins. Nav rail condenses into a bottom floating HUD or full-screen menu overlay; data cards replace multi-column grids.

### Operational Spacing Cadence
- Form inputs, segmented tabs, and compact grid cells adhere strictly to a dense 4px base step (`0.25rem`).
- Module internal padding consistently utilizes `space-md` (16px) for compact widgets, or `space-lg` (24px) for analytical dashboards and stage views.

## Elevation & Depth

Visual hierarchy uses frosted glass layers, internal light reflections, and luminous edge highlights instead of traditional heavy dark drop shadows.

### Elevation Levels

1. **Surface 0 (Substrate Floor):** `#090D14` solid. Baseline for global workspace background.
2. **Surface 1 (Primary Glass Panels & Grids):** 
   - Background: `rgba(13, 19, 31, 0.70)`
   - Backdrop Filter: `blur(16px)`
   - Border: `1px solid rgba(255, 255, 255, 0.06)`
   - Shadow: `0 4px 20px -2px rgba(0, 0, 0, 0.5)`
3. **Surface 2 (Floating Modals & Flyouts):**
   - Background: `rgba(19, 29, 46, 0.85)`
   - Backdrop Filter: `blur(24px)`
   - Border: `1px solid rgba(16, 185, 129, 0.20)`
   - Shadow: `0 12px 36px -4px rgba(0, 0, 0, 0.75), 0 0 16px -2px rgba(16, 185, 129, 0.08)`
4. **Surface Luminous (Active & Flagged Nodes):**
   - Background: `rgba(13, 19, 31, 0.90)`
   - Border: `1px solid rgba(52, 211, 153, 0.40)`
   - Shadow: `0 0 24px -2px rgba(16, 185, 129, 0.25), inset 0 1px 0 rgba(255, 255, 255, 0.15)`

### Micro-Glow Protocol
Interactive triggers and key metrics emit subtle ambient light fields. Cyan glows denote computational activity (`0 0 12px rgba(6, 182, 212, 0.25)`), while Emerald glows (`0 0 16px rgba(16, 185, 129, 0.30)`) signal solvency, system compliance, and authorization readiness.

## Shapes

The design system maintains a **Soft-Precision (`1`)** shape language, communicating institutional durability, modular structure, and surgical clarity.

### Radius Definitions
- **Base Element Corner (`0.25rem` / 4px):** Checkboxes, inline code badges, context chips, micro table tags.
- **Component Standard (`0.5rem` / 8px):** Buttons, text inputs, dropdown panels, wizard nodes, metric cells.
- **Surface & Modal Container (`0.75rem` / 12px):** Data cards, slide-over panels, master modals.
- **Pill Geometry (`9999px`):** Status indicator pills, active workflow badges, user presence rings.
